# ANGLE: Effort scaling and progressive delivery — turning budget into answer quality, against the arithmetic and the serial executor this repo actually has.

On this machine effort scaling cannot buy latency and it is a mistake to design as if it could. `Engine::spawn` (engine.rs:3150-3182) recurses into `self.run(&mut child_run, ...)` on the caller's thread, and `OLLAMA_NUM_PARALLEL=1` serialises the model regardless — so the tree's wall-clock is the SUM of every agent's, `run.spent.add(&child_run.spent)` rolls all six dimensions up, and `Budget::interactive()`'s `subagents: 8` is a whole-tree headcount inside a 600,000 ms whole-tree serial clock. The only currency effort scaling can spend is quality-per-token. The harness gives the PI nothing to spend it with: nothing in the workspace renders remaining budget into a window (grep for `remaining` outside budget.rs returns one unrelated comment), `BudgetShare` is a three-valued enum chosen at spawn from no evidence, and there is no path by which "the first pass found a contradiction" produces more effort. Two concrete defects sit under A2 and would silently decide its cells: `Budget::grant` floors `tokens` at `MIN_CHILD_TOKENS = 3_601` and floors `wall_ms` at **1 ms**, on a box where the 27b cold-loads in 11,410 ms; and the pause note at engine.rs:3233 prints the exhausted dimension correctly then interpolates **token** numbers and prescribes `budget_tokens` — so a wall-starved child tells its parent to turn the wrong knob. Progressive delivery is 90% built and mis-keyed: `ControlPlane::frames_since` is a per-run frame ring on a second listener, but `daemon.rs:2526` pushes every frame under one `key_for_sink` (the root run id) and `QuarantinedSink` drops child prose upstream of it, so `--watch <child>` can never show anything.

## The tail ledger — the PI can read what it has left

- **What:** One harness-authored line at the TAIL of the window each iteration: tokens/wall_ms/subagents/depth remaining, plus what the last child was granted versus what it actually spent. Today a model asked to scale effort is guessing: it learns a budget exists only from a refusal string or a `[child stopped]` note after the money is gone. A2's 'budget-proportional' arm has no input signal without this and would be measuring the model's prior, not its arithmetic.
- **Mechanism:** `Budget::remaining(&run.spent)` already exists (budget.rs:165) and is computed at every iteration top. Render it as `Block::new(SourceKind::History, ..., TrustClass::AgentObserved)` using exactly the `[spawned]` receipt pattern at engine.rs:2990 — no new `SourceKind` (the `ALL` array is a pinned 11-variant list with a counted self-check) and no new struct field. It MUST sit at the window tail: STATE.md's 148-byte front-of-prefix change cost 1.45 s of TTFT, and a per-turn-changing line in the stable tier churns the prefix on every turn. Pair it with the `grant_tokens: Option<u64>` escape hatch `Budget::grant` already honours, so the model has a number to read AND a field to write.
- **Gain:** A solo call has one budget and no allocation decision to make, so this buys it nothing. The team's PI makes N allocation decisions per task and currently makes every one blind — it cannot tell whether it is on its first child of eight or its seventh, and `run.spent.add(&child_run.spent)` means a single verbose grandchild can consume the headcount silently. The gain is not intelligence, it is that the PI's spend decisions stop being uniform random over the tree.
- **Cost:** ~40 tokens per iteration at the window tail, prefix-safe by construction. Zero extra model calls, zero wall-clock. Build: half a day.
- **Read by:** No new field. The renderer reads `Budget::remaining`; the model reads the block; the model's answer is read back by `Budget::grant`'s `explicit` parameter (budget.rs:214). Because the ultimate reader is the model, the test must assert on the `--dev` outbound-request dump of the RUNNING process, never on a block built in a test process — that is the `persona_emission.rs` failure aimed at a budget control.

## wall_ms has no floor, and its exhaustion note prescribes the wrong knob

- **What:** Fix the two halves of a starvation channel that A2 would otherwise silently measure. (a) `Budget::grant` refuses a token grant below `MIN_CHILD_TOKENS` by name (`PoolTooSmall`, `BelowFloor`) and floors `wall_ms` at **1 ms** via `at_least_one_u64`. A depth-3 Standard leaf gets 31,640 ms; a 27b cold-load is 11,410 ms — 36% of the leaf's entire wall budget — and a fourth sibling gets whatever milliseconds remain, with no refusal. (b) engine.rs:3233 formats `"it ran out of {dimension} after spending {} tokens of the {} it was granted... Give the next one more budget_tokens"` — dimension correct, both numbers tokens, remedy wrong. A PI that obeys re-spawns with more tokens and the same wall and fails identically.
- **Mechanism:** Add `MEASURED_CHILD_FIRST_CALL_WALL_MS` beside `MEASURED_CHILD_FIRST_CALL_TOKENS = 3_089` (budget.rs:56) — **read from the journal, not invented**, exactly as that constant's own doc comment demands. Add `GrantRefused::WallTooShort { want, min }` carrying both numbers. Change the pause arm to interpolate the exhausted dimension's own spent/granted pair. Note that `a_leaf_at_depth_four_is_inside_the_declared_band` (budget.rs:596) cannot see any of this: it uses `depth: 4` while the product ships `depth: 3`, passes `&Budget::default()` as `spent` at every level so it only ever measures the FIRST sibling, and asserts on `tokens` alone.
- **Gain:** This is the tax a team pays that a solo call does not: a solo run holds the whole 600,000 ms and never divides it. Every division is a chance to hand a child a budget it cannot use, and the failure is invisible — the parent reads a plausible sentence about tokens. Fixing it is what makes 'more agents' able to help at all.
- **Cost:** Zero tokens, zero wall-clock at runtime. One to two days. Trades away nothing; it strictly narrows what `grant` may hand out.
- **Read by:** `Budget::grant`'s new refusal branch reads `MEASURED_CHILD_FIRST_CALL_WALL_MS`; `Engine::spawn`'s `PauseReason::BudgetExhausted` arm reads the dimension to pick which spent/granted pair to print. Both are existing functions — no declared-and-unread field.

## Effort scaled by what the reader FOUND — the disagreement field

- **What:** Effort should rise when the evidence says the question is harder than it looked, and nothing in the harness expresses that. The quarantined reader is the one component that holds several sources in one window simultaneously — ADR-041 concedes this as the fidelity trade — and it is therefore the only place in the system positioned to notice that source_2 contradicts source_4. That observation is discarded today. Add one field to its contract, and let the PI's next-round effort read a harness-computed count of chunks that reported one.
- **Mechanism:** `Engine::condense_chunk` (engine.rs:2320-2328) builds `vec![FieldSpec::text("about").capped(600)]` plus one `FieldSpec::text(source_label(i))` per source. Append `FieldSpec::line("disagreement")` — `FieldType::Line`, cap 200, so it structurally cannot contribute a second line to `CondensedResult::render()`. It costs no extra model call: the reader is already running and already holds every source. The parent sees it through the existing `condensed_note` closure.
- **Gain:** The harness never puts raw pages in a working window, so a solo PI cannot cross-compare sources at all — it sees N independent summaries and would have to infer conflict from prose. The batched reader gets a forced side-by-side comparison for free, and this is the one signal the multi-agent structure produces that a single context provably cannot. It is also the only currently-available input for 'spend more because of what was found' rather than 'spend more because the question looked long'.
- **Cost:** +200 characters per reader chunk (~50 tokens), against `PER_SOURCE_MAX_CHARS` already in the thousands. Zero extra model calls, zero wall-clock. The real cost is a security question, below.
- **Read by:** `OutputContract::validate` and `FieldSpec::validate_value` read the spec (existing); `condensed_note` renders it; the count is computed by the caller and lands in the tail ledger of idea 1. **The security cost must be raised, not designed around:** a hostile page can manufacture a disagreement to buy itself more of the run's budget. Every source is `UntrustedContent`, so ADR-036 §5's saturation lesson applies — the trust floor cannot discriminate here and the question is who asserted it. The answer must be that effort is raised by a HARNESS-COUNTED number of chunks, never by the reader's prose, and that the signal may raise spend but may never name a host, a URL or a tool — spend-as-Target under ADR-023 is a genuine open question and is the human's.

## Loop-until-dry with a harness-computed saturation stop

- **What:** Replace 'fixed 3 rounds' with 'keep going while new sources are still new', using a signal that costs zero model calls and that untrusted content cannot argue with. A research pass whose latest batch was 5 of 6 cache hits has saturated; one at 6 of 6 fresh has not.
- **Mechanism:** `Engine::condense_chunk` already keys `self.condensed` on `content_key(&p.text)` — CONTENT, not URL, so two URLs serving identical bytes collapse — and builds a `cached: Vec<Option<String>>` alongside `fresh`. The novel-source ratio is `fresh.len() / chunk.len()`, already in scope, currently thrown away. `self.condensed` lives on the `Engine`, and because children run serially inside the parent's call stack it is shared across the whole tree for free. Surface the ratio in the existing `subagent` ToolLine summary (already `Metric::Count`, harness-authored) and in the tail ledger.
- **Gain:** A solo model deduplicates by recalling what it read and is unreliable at it, especially after compaction. The cache is exact, content-keyed, and — this is the team-specific part — shared across every agent in the tree, so agent 5 gets credit for what agent 2 already read. That cross-agent dedup is not available to a solo run at all, and it is what makes wider fan-out cheap instead of quadratic.
- **Cost:** Zero tokens, zero model calls, zero wall-clock. It only ever stops work earlier, so it saves tokens. Build: a day.
- **Read by:** `Engine::condense_chunk`'s existing `cached`/`fresh` split is the producer; the ToolLine summary and the tail ledger are the readers. No new field on any struct.

## Progressive delivery: per-child frames, and validated artifacts as the unit of delivery

- **What:** Two fixes that make 'the conversation never halts' literally true. (a) Key run frames by the run that emitted them, so `--watch <child>` shows that child. (b) Make the delivered unit a real file the user can open mid-run, not a stream — a child writes `runs/<run>/findings-N.md` and returns `{path, claim_count}`, so the parent's window holds 200 characters instead of 2,000 and the user has something readable before the tree finishes.
- **Mechanism:** `daemon.rs:2526` pushes every frame under one `key_for_sink = run_id.to_string()` (the root's), so the plane's per-run `Frames` ring is populated for exactly one key; `ControlPlane::frames_since(run, since)` and `MAX_FRAMES = 2_000` with coalescing already do the rest. Upstream, `Engine::spawn`'s `QuarantinedSink { inner: ports.sink }` drops `TextDelta`/`ReasoningDelta` — correctly, per audit finding E4 and `nothing_the_quarantined_reader_says_reaches_the_surface`. So the honest version streams STRUCTURAL frames per child (spawn line, tool lines, budget) and delivers the child's PROSE only once it has crossed `req.contract.validate` at engine.rs:3216 — progressive delivery of artifacts, not of tokens, which needs no new E4 DECISIONS entry. The artifact half needs no new tool: `write` is in `BUILTIN_TOOLS` (builtin.rs:37), `SourceKind::ProjectFiles` has 15% of the window and daemon.rs:2664 now actually fills it, so re-reading a finding is a `read` call rather than permanent context residency.
- **Gain:** A solo model producing a 10-minute report shows the user nothing until it finishes; its intermediate state is context, and context is not addressable. A tree has N runs that each reach a validated boundary at a different time, and `ChildResults` is budgeted at only 5% of the window (10,000 tokens) — so artifacts are not a nicety, they are what stops the PI's window being the bottleneck on how much research the team can hold. Quality per token improves because the parent pays 200 characters for a finding instead of 2,000.
- **Cost:** Frame re-keying: a day, near-zero runtime. Artifacts: each child pays one `write` tool call (~0 model tokens, milliseconds) and saves the parent ~1,800 characters of `ChildResults` per child. Trades away: the user can no longer watch a child think, only what it has finished — deliberate, and E4 requires it.
- **Read by:** `ControlPlane::push`/`frames_since` read the new key; `watch_client.rs`'s `apply` renders the frames (both exist). For artifacts, `OutputContract::validate` reads a `FieldSpec::line("path")`, and the file is read back by the `read` executor — the reader is a shipped tool, not a new one.

## A2 with the control that separates 'more agents' from 'more tokens'

- **What:** Run A2's three arms (fixed 3 / complexity-scaled / budget-proportional) plus a FOURTH cell that is not in M3-DESIGN §9.1: the solo PI given exactly the token budget the winning team arm actually consumed. Without it every A2 result is 'more tokens helped' wearing a team's clothes, because `run.spent.add(&child_run.spent)` guarantees the higher-fan-out arm spends more tokens by construction. ROADMAP's bar is literally 'competitive on the same model' — so the solo-at-matched-tokens cell IS the acceptance criterion, not a nicety.
- **Mechanism:** Pre-register in `tools/preregister_m3_a2.py` (the `fit_gate.py` pattern: the tool refuses to run without the file). Each arm writes its own profile root; the totals come from the `run_completed` journal row, which already carries the rolled-up tree spend, read with `tools/read_journal.py --kinds all --json`. Quality is RACE and FACT citation accuracy on the same fixed question set. The un-instrumented control is the same arm run with the tail ledger and disagreement field absent.
- **Gain:** It does not — it is the instrument that decides whether anything else here does. Its value is that it is the only design in which a null result is legible: three team arms with no solo-at-matched-tokens cell produce a sheet that reads 'the team helped' whether the team helped or the tokens did.
- **Cost:** Four cells x N questions x ~10 minutes of serial wall each. On this box a 20-question set is roughly 13 hours of wall per full sweep, and the sweep must not share the checkout with a `cargo build` (hazard form 6 inflates every timing ~10%). Tokens: ~200k per cell per question at the root cap.
- **Read by:** `tools/preregister_m3_a2.py` reads its own registration file and refuses without it; `tools/read_journal.py` reads the `run_completed` rows. No new product field at all — the arm identity lives in the journal as provenance, and per the `upward_shape` precedent at engine.rs:3000 **no cell is ever read from that row**, because it moves with the flag rather than with the behaviour.

**measurement:** Quality per token = (DeepResearch Bench RACE score, and FACT citation accuracy) divided by the root's rolled-up `spent.tokens`, both read from the same `run_completed` journal row so quality and cost are never taken from different runs: `python tools/read_journal.py --profile-root runs/m3-a2/<arm> --kinds all --json | jq -s '[.[]|select(.kind=="run_completed")]|{tokens:.[0].payload.spent.tokens, wall_ms:.[0].payload.spent.wall_ms, subagents:.[0].payload.spent.subagents}'`, one line per question, against the arm's RACE/FACT sheet. THE CONTROL THAT MAKES IT MEAN ANYTHING is the fourth cell: the solo PI (`subagents: 0` by giving the root profile no `run`, structurally, never `subagents: 0` — that is instance #17) at the token budget the winning team arm consumed. If solo-at-matched-tokens ties the team arm, the finding is that the tree is decorative and it is worth more than the feature. Second control, for the tail ledger and disagreement field: run the identical arm with the ledger showing a CONSTANT — if refusal counts and spend patterns move identically, the model is reacting to the presence of budget talk rather than to the numbers, which is instance #15 in an effort-scaling control. Two cheap in-repo numbers that need no benchmark at all: `cargo test -p marlowe-loop --lib budget -- --nocapture` printing the leaf share at the SHIPPED `depth: 3` with non-zero `spent` for the second and third siblings and with the `wall_ms` column included (the existing `a_leaf_at_depth_four_is_inside_the_declared_band` shows none of those three things); and a journal scan for `run_paused` rows whose dimension is `wall_ms` and whose child spent fewer than 3,089 tokens — every such row is a child that died before it could speak, and today the parent was told to raise `budget_tokens`.

**cheapest_first_step:** Before designing anything: print the budget the product actually hands out, on the dimensions and at the depth it actually ships. Extend `a_leaf_at_depth_four_is_inside_the_declared_band` (crates/marlowe-loop/src/budget.rs:596) into a `--nocapture` printer that walks `Budget::interactive()` at its real `depth: 3`, grants THREE siblings at each level with the running `spent` fed back in rather than `&Budget::default()`, and prints tokens AND wall_ms AND micros_usd per leaf. Two claims fall out in one command with no model, no network and no benchmark: whether the third sibling's wall grant drops under the 11,410 ms cold-load figure with no refusal path (the existing test cannot see this — it measures the first sibling only, on tokens only, at a depth the product does not use), and what the shipped depth-3 leaf share actually is (5.27% by hand: 200,000 -> 75,000 -> 28,125 -> 10,546 tokens, and 600,000 -> 225,000 -> 84,375 -> 31,640 ms). If the wall column is fine, idea 2 shrinks to the one-line message fix at engine.rs:3233 and the session moves straight to the tail ledger.

**biggest_risk:** The disagreement-driven effort trigger makes untrusted content an input to how much the run spends, and no existing layer covers that. Every source is `UntrustedContent`, so the trust floor is saturated and — per ADR-036 §5, the most general lesson in CLAUDE.md — a floor that reads 'blocked' for every value says nothing about any of them. A hostile page that claims the other sources are wrong manufactures a signal that buys itself more of the tree's budget and more of the PI's attention. It is not an escalation (no tool, no target, no argument), it is a resource-allocation influence, and 'is spend a Target under ADR-023' is undecided. The mitigation that keeps it shippable is that the effort input must be a HARNESS-COUNTED number — how many chunks reported a disagreement, what fraction of a batch was novel — never the reader's prose, and it may raise the amount spent while never naming what it is spent on. The second-order risk is that the whole angle is confounded: because `run.spent.add(&child_run.spent)` rolls child spend into the parent, more agents always means more tokens, so every A2 cell without the solo-at-matched-tokens control reads identically whether the team helped or the tokens did.

# ANGLE: Verification — the DeepResearch Bench FACT ≥95% row, won by making most of the check mechanical over bytes the harness already stored, and spending model calls only on the residue a matcher cannot decide.

The substrate for citation verification is already built and nobody has connected it. ADR-042 put every fetched document whole into `marlowe_extract::store::DocumentStore` (`crates/marlowe-extract/src/store.rs`), content-addressed by BLAKE3 over the extracted text, dereferenceable through `DocumentStore::text(hash)` / `get(hash)`. So a verifier can check a quote against the exact bytes that were fetched, with no model in the loop and no network. Crucially, a verdict computed from those bytes is `AgentObserved`, not `UntrustedContent`, by ADR-042's own argument at `crates/marlowe-exec/src/lib.rs:1798-1875` — the harness authored every character of it and a boolean cannot carry an instruction. That means mechanical verification is free of the layer-1 quarantine tax entirely. The team wins this row not by voting but by *asymmetry*: the 27b PI writes the report holding the whole justification in its window, which is exactly the anchoring the FACT judge penalises; a 4b intern that has seen only (span, claim) and nothing else is structurally unable to be anchored, and on that one narrow judgement AAII 20 and AAII 52 are much closer than the ladder suggests. Two hard blockers: `build_tool_host` is called inside `turn` (`crates/marlowe-daemon/src/daemon.rs:2497`), so the store is per-turn and `read_ref` already tells the model "refs last for this session" — a research pass spanning turns cannot verify itself; and there is no DeepResearch Bench harness anywhere in this repo, so the 95% row is currently unmeasurable.

## The mechanical citation ledger — verification at AgentObserved, zero model calls

- **What:** A harness-side `CitationLedger` over `DocumentStore`, plus a `cite` tool taking `{ref, quote, claim?}`. It locates `quote` in `store.get(ref).text` by three escalating matchers (exact substring → NFKC + whitespace/case-folded substring → token-n-gram span match with a scored best window) and returns byte offset, match tier, and a harness-authored verdict line. Four checks are decided outright with no model: (1) the ref was never stored → fabricated citation; (2) the citation names a URL that is not `DocumentRef.url` for that hash → wrong-source binding; (3) the quote appears nowhere → hallucinated quote; (4) digits in the claim ("47%", "1,200", "2019") that appear nowhere within ±N chars of the located span → number drift. Two more are decided from `DocumentRef.warnings`, which are already fixed harness strings: a citation into a document carrying `no-text-layer(needs-ocr)` has no text to support it, and one carrying `likely-client-rendered` is not what a reader would see.
- **Mechanism:** New module `crates/marlowe-exec/src/cite.rs` (or `marlowe-extract/src/cite.rs` if the matcher should sit beside the store). Reads `marlowe_extract::store::DocumentStore::get`/`text` and `DocumentRef.{url, warnings, chars}`. Dispatched from `FileSystemTools::dispatch` (`crates/marlowe-exec/src/lib.rs:1994`) alongside the existing `read`/`web` arms; `executes()` at `:1890` gains `"cite"`, which `every_declared_tool_has_a_match_arm` already enforces agreement on. Returns a `ToolOutcome` with `Metric::Count{n, unit:"verified"}` / `Metric::State("unsupported")` and `trust: TrustClass::AgentObserved` — licensed by exactly the comment at `lib.rs:1830-1875`, since no substring of the page appears in the result. Batches through the existing `execute_batch` path, so 60 citations are one round, not 60.
- **Gain:** It is not a model doing it at all, which is the point. A solo 27b asked "check your citations" re-reads its own report and its own reasoning — the FACT judge's failure mode reproduced inside the writer. Here the *harness* holds the ground truth (the bytes it fetched) and the writer cannot talk its way past a substring match. The team gain is that the PI is freed from a task it is structurally bad at, and the check runs at zero marginal tokens so it can be applied to every citation rather than a sample.
- **Cost:** Zero model tokens. Matching cost is Rust over an in-memory `String`: exact and folded substring are linear, the n-gram window is the only real work — for a 2.2 MB paper (the arXiv 1706.03762 case in `examples/deep_research.rs`) budget single-digit milliseconds per quote, and it must run off the daemon thread through `execute_batch`'s existing unconditional offload. Trades away: it can only verify against documents fetched in the same turn (see idea 4), and it cannot decide entailment — a quote can be present and still not support the claim.
- **Read by:** `CitationLedger::verify` reads `DocumentStore::get`; the writer reads the returned verdict metric; `CitationLedger::unresolved_count()` is read by the report-write gate. No new field on a pinned type.

## The two-stage funnel — mechanical gate, then one batched entailment jury on the survivors only

- **What:** Stage 1 is the ledger. Every pair it decides is done. Stage 2 spawns Agent-Low (`marlowe-mini:4b-super`) children over only the pairs where the quote WAS found — the residue where the question is genuinely "does this span support this claim". Each child sees a harness-composed brief containing nothing but N (span, claim) pairs under harness-assigned labels, and returns one short verdict per pair. It never sees the report, the writer's reasoning, the URL, the other pairs' verdicts, or the run's task.
- **Mechanism:** Reuses `Engine::condense_batch`'s shape wholesale (`crates/marlowe-loop/src/engine.rs:2224`): chunking, `source_label(i)` → here `claim_label(i)`, the harness-assigned-label defence that `each_source_is_reported_under_its_own_harness_assigned_label` already asserts (`engine.rs:1188`), and the fresh-index bug fixed at `:2610`. Contract is `OutputContract::structured("judge each claim against its span", vec![FieldSpec::line(claim_label(i)).capped(24), ...])` — `structured` derives the aggregate from the per-field caps, which is the C3/E8 fix at `run.rs:376`. Spawned with `SpawnRequest{ role: ModelRoute::Worker, disposition: Disposition::Work, reads_untrusted: true, tools: vec![] }` — `reads_untrusted` forces `EgressPolicy::DenyAll` through `CapabilityProfile::new`, so a jury that reads attacker prose still cannot act.
- **Gain:** Two independent mechanisms, both structural. (1) Anchoring: the writer holds its justification; the juror is given a window that provably contains only the span and the claim, so there is no justification to be anchored to. This is not a prompt instruction, it is what is in the context. (2) Ladder economics: 52→22 is a cliff but 22→20 is inside the noise, and "does this 200-token span entail this one sentence" is precisely the task where that flat region holds — it is a local judgement with no planning, no tool use, and no long-range coherence. Paying AAII 52 for it is the wrong allocation, and paying it *by the writer* is the wrong allocation twice.
- **Cost:** One model swap. The 27b cold-loads in 11,410 ms and this card evicts rather than co-residing, so verification must be ONE phase at the end, not interleaved per citation — interleaving costs 2N × 11.4 s and is catastrophic. Per batch of 8: roughly 8 × (200-token span + 40-token claim) + brief ≈ 2.1k prefill, ~120 tokens out. Under `OLLAMA_NUM_PARALLEL=1` same-role workers serialise, so fan-out buys nothing and batching is the only lever available — every one of these numbers is an estimate to be measured on this box, not inherited. Trades away: batch width introduces cross-claim contamination (claim 3's span can discuss claim 5), the same fidelity risk ADR-041 named for `MAX_SOURCES_PER_READER`.
- **Read by:** The per-pair verdict field is read by `CitationLedger::record_jury_verdict`, which is read by the report-write gate and by the FACT scorer. `OutputContract::validate` reads the field specs, as today.

## The planted-error control, typed by class and pre-registered — without which 95% is not evidence

- **What:** A verifier that answers "supported" to everything scores ~99% on an honest corpus, which is better than a real one. So the pass is scored on a set with harness-authored known-bad pairs at a pre-registered rate, in five classes, and the result is reported PER CLASS and never aggregated: F1 fabricated ref (a hash never stored); F2 swapped source (claim from doc A, ref pointing at doc B, both real and both fetched); F3 negated claim (span says X, claim says not-X — nearly all the same words); F4 number drift (span says 47%, claim says 74%); F5 over-generalisation (span says "three trials in mice", claim says "in humans"). F1/F2/F4 must be caught 100% by stage 1 or the ledger is broken. F3/F5 are mechanically undetectable by construction and are therefore the ONLY cells that measure whether stage 2 does anything at all.
- **Mechanism:** `tools/preregister_fact_control.py` writes the plant set and the predicted per-class catch bands to `runs/m3-fact/PREREGISTRATION.json` before any run; `tools/score_deepresearch_fact.py` refuses to run without it, exactly as `fit_gate.py` refuses without `tools/split.json`. Plants are generated from the corpus the run actually fetched, so F2's decoy is a real `DocumentRef` and F1's hash is a real-shaped BLAKE3 hex that `DocumentStore::contains` returns false for. Plants run in separate batches from honest pairs so a batch's composition cannot be inferred in-context — a 20% plant rate inside one batch teaches the juror the base rate.
- **Gain:** It does not beat solo; it is what makes the team claim auditable. The specific finding it exists to prevent is this project's own #15 and the A8 amendment one subsystem over: three verifier arms producing identical sheets reads character-for-character like 'verification works'. If `real ≈ mechanical-only` on F3 and F5, the jury is decorative and the 95% belongs to the substring matcher — a finding worth more than the feature, and one that only a per-class breakdown can produce.
- **Cost:** Plant generation is offline and free. Scoring cost is the plant rate times the honest pass — a 20% plant rate is a 20% surcharge in tokens and wall-clock on the verification phase only, which is the cheap phase. Trades away: plants are harness-authored and may be systematically easier than real errors. The check on that is the disagreement rate between the mechanical-only and real arms on the HONEST corpus, which must be non-zero.
- **Read by:** `score_deepresearch_fact.py` reads `PREREGISTRATION.json`'s bands and refuses without it; the per-class `caught/planted` counters are read by nothing but the printed sheet, deliberately — no product code reads a plant.

## Give the DocumentStore a lifetime longer than a turn

- **What:** `build_tool_host` is called inside `turn` at `crates/marlowe-daemon/src/daemon.rs:2497`, constructing a fresh `FileSystemTools` and therefore a fresh `DocumentStore::new()` every turn. `read_ref`'s own error text says so out loud: "Refs are reported by `web` and last for this session; fetch the URL again if you need it" (`marlowe-exec/src/lib.rs:1635`). The brief's target case is the overnight report — "look into X while I sleep", morning, fifteen pages, every citation verified — which spans many turns, and progressive delivery guarantees it does. Verification of a citation fetched three turns ago is currently impossible. Hoist the store to profile scope, content-addressed on disk, with an eviction policy.
- **Mechanism:** `FileSystemTools::with_store` already exists (`marlowe-exec/src/lib.rs:367`) and `DocumentStore` is `Clone + Send + Sync` over `Arc<Mutex<BTreeMap>>`, so the change is to build one store where `Daemon` is built and hand it to `build_tool_host` rather than constructing one inside it. Persistence goes beside the journal under `Profile`, addressed by the same BLAKE3 hex.
- **Gain:** It is what makes a multi-turn team possible at all: the PI's verification phase and the interns' fetch phase are necessarily different turns once progressive delivery ships, and today the bytes are gone in between. Without it, every research pass must be one monolithic turn, which forfeits resume, steering and progressive delivery — three things M3 exists to ship.
- **Cost:** Disk proportional to the corpus (the 24-document example moved MB, a real pass will move hundreds), plus an eviction policy and its own test. Genuine security surface: a persisted store is a persisted corpus of attacker-authored bytes, and its lifetime is now measured in days. It changes nothing about trust — `read_ref` already returns `UntrustedContent` with the note "a document does not become trustworthy by being written down and read back" — but it does widen what a later compromise can reach, and the collision-refusal branch at `put_addressed` becomes load-bearing across sessions rather than within one.
- **Read by:** `DocumentStore::text`/`get`, called by `read_ref` (`lib.rs:1630`) and by `CitationLedger::verify`. No new field — the change is a construction site, not a schema.

## Make the leaf return quotes, not only prose — a checkable child→parent crossing

- **What:** The quarantined reader's research contract returns `source_N: <1,500 chars of summary>`. A summary is unverifiable by construction: there is no span to check it against, so every downstream citation is an assertion. Add, for the RESEARCH reader only, `source_N_quote` (a short `FieldSpec::text`) beside the summary. The harness then mechanically confirms the returned quote is a substring of the specific document that child was handed — which is a property `OutputContract::validate` cannot express today.
- **Mechanism:** A second contract constructed alongside the one at `engine.rs:2326`, and a post-`validate` step in `Engine::spawn`'s note match (`engine.rs:~2911`) that calls `CitationLedger::verify` on each returned quote against the store hash for that source slot, rejecting or flagging a quote that is not present. The label→document binding is already harness-assigned and already tested (`each_source_is_reported_under_its_own_harness_assigned_label`), which is exactly what makes this check meaningful — the harness knows which document `source_3` was.
- **Gain:** This is the seam a solo model has no equivalent of. In a single context the model's claim about a page and the page are the same object; here they are separated by a spawn boundary the harness controls, so the harness can hold one against the other. It converts the `UntrustedContent → AgentInferred` crossing at `run.rs`'s FieldSpec — today validated only for shape — into one where at least one field is provably derived from measured bytes.
- **Cost:** Widens the reader's per-source output, so `OutputContract::structured`'s derived aggregate grows and the reader's token slice with it — the E8 arithmetic-unsatisfiability trap is live here and the aggregate must be re-derived, not assumed. Trades away: a quote is one span, so a summary synthesising three paragraphs has no single supporting quote and will flag; that is a real product cost and an argument for allowing 0..k quotes rather than exactly one. AND THE HARD PART: `OutputContract` is a field of `SpawnRequest`, which CONTRACTS §5.0 pins (ADR-064). This is a raise-it, not an edit-it, and the research contract must be a separate object from the layer-1 quarantine contract or a research feature is editing a security boundary.
- **Read by:** `CitationLedger::verify` reads `source_N_quote` against the store hash for slot N; `Engine::spawn`'s note match reads the resulting verdict to decide whether the field crosses. New field, and it has a reader before it has a producer.

## Adversarial framing as an ARM, not a default

- **What:** Run the entailment juror in three framings on the same pairs: (a) neutral "does this span support this claim", (b) refute-first — write the strongest case that the span does NOT support the claim, then verdict, (c) verdict-only with no reasoning field. Score per plant class and on the honest corpus separately.
- **Mechanism:** One field difference in the jury contract: (b) adds a `FieldSpec::text("objection_N").capped(300)` before the verdict line; (c) drops any reasoning field. Same `condense_batch` chunking, same harness labels. - **Gain:** A single model has one framing. A team can afford to hold the framing as a variable and measure it, and the interesting result is likely the negative one: refute-priming should raise catch rate on F3/F5 AND raise false-unsupported on the honest corpus, which is a real tradeoff the FACT metric is sensitive to in both directions (accuracy is supported/total, so over-refusing costs effective citation count).
- **Cost:** 3× the verification phase, serialised by `OLLAMA_NUM_PARALLEL=1`. Arm (b) roughly triples the output tokens per pair (300-char objection vs a 24-char verdict), so it is the expensive arm. Run once as an arm, then pin one framing; do not ship three.
- **Read by:** The `objection_N` field is read by nothing in the product — it exists to change the model's computation and is discarded. **measurement:** `python tools/score_deepresearch_fact.py --out runs/m3-fact/<label> --target "exec://../target/release/marlowe.exe --profile-root {profile_root} ..." --plants runs/m3-fact/PREREGISTRATION.json --verifier <none|stub-yes|real> --report tokens,wall_ms` — printing `citation_accuracy`, `effective_citations`, `caught/planted` for each of F1..F5 separately, total tokens, and wall-clock. Asked the way this project asks it: an always-yes juror on an honest corpus reads ~99% citation accuracy, BETTER than a working one. So the honest-corpus number alone reads identically whether verification works or is deleted, and it is not evidence at all — only the per-class planted cells discriminate, and they must be reported un-aggregated. Second control, on the plants themselves: the honest-corpus disagreement rate between `none` and `real` must be non-zero, or the plants are easier than reality and the planted sheet is measuring a synthetic task.

**cheapest_first_step:** Measure the mechanical ceiling offline, before writing any tool or spawning any model. **biggest_risk:** Two, and the second is worse. Building the verifier before the scoreboard risks tuning against intuition; building the scoreboard first risks discovering the substrate cannot be measured through the eval adapter, which speaks to a process with no loop and no tools and can therefore never exercise the funnel.

A2's budget-proportional arm without this measures the model's prior, not its arithmetic.

**Not** a `Block::new(SourceKind::History, ...)` pushed into `state`, which the first draft of this proposed and which is wrong twice: `History` is not trimmable (context.rs:156-170, and `trim_to_budget` keeps non-trimmable blocks unconditionally at 698-700), so a per-iteration push accumulates untrimmably for up to `MAX_STEPS = 400`; and every earlier ledger stays in the window, so the model reads N contradictory budget lines. **Author it in the assembler at assemble time**, the way the stable tier constructs the `Identity` block on every assemble: one block, at the tail, regenerated each turn, never persisted. ~40 tokens, prefix-safe by construction (STATE.md, 2026-08-27: 148 bytes at the FRONT cost 1.45 s), zero model calls.

**Its control, and this is the part that makes it evidence:** run the identical arm with the ledger showing a **constant**. If refusal counts and spend patterns move identically, the model is reacting to the presence of budget talk rather than to the numbers. Assert on the `--dev` outbound-request dump of the RUNNING process (daemon.rs:2131), never on a block built in a test process — that is `persona_emission.rs`'s failure aimed at a budget control.

### Step 4 — loop-until-dry on the cache ratio (free, and the only cross-agent signal)

`condense_chunk` already keys `self.condensed` on `content_key` — **content, not URL** — and already builds `cached`/`fresh` (engine.rs:2259-2268). The novel-source ratio `fresh.len() / chunk.len()` is in scope and thrown away. `self.condensed` lives on the `Engine` (engine.rs:437) and children recurse through `self.run`, so **the cache is shared across the entire tree for free**: agent 5 gets credit for what agent 2 read. A solo run has no equivalent — it deduplicates by recall, unreliably, and not at all after compaction. `MAX_CONDENSE_CACHE = 512`, cleared wholesale (engine.rs:2602). A batch at 5-of-6 cache hits has saturated; 6-of-6 fresh has not. Surface the ratio in the `subagent` ToolLine, which already carries `Metric::Count { n: child_run.spent.tokens, unit: "tokens" }` (engine.rs:3381), and in the tail ledger. Zero tokens, zero model calls, and it only ever stops work earlier.

**DEFERRED, deliberately: the reader's `disagreement` field.** `OutputContract::validate` returns `MissingField` for any declared field the reader omits (run.rs:415), a violation is *not* fatal — it goes into the child's window and the loop continues — and `OutputContract::structured`'s own doc comment records that this is audit finding E8's engine: *"burned up to a quarter of the parent's budget per group and returned nothing for all six documents."* A 4b reader with nothing to report will omit the field. There is no optional-field concept. Nothing would read it either: the `Completed` arm copies exactly `about` and `source_N` (engine.rs:2489-2493). If it is ever built it needs a stated sentinel in the contract description, a read site, and a fixture of six non-conflicting documents asserting `contract_retries == 0`. The cache ratio gives an evidence-driven trigger with none of that exposure.

### Step 5 — A2, with the control that is the acceptance criterion

Three arms (fixed 3 / complexity-scaled / budget-proportional) plus a **fourth cell not in M3-DESIGN §9.1: the solo PI at the wall-clock the winning team arm consumed** — matched on WALL, not tokens, per the reframe. ROADMAP's bar is literally *competitive on the same model*; `run.spent.add(&child_run.spent)` guarantees the higher-fan-out arm spends more of everything by construction, so three team arms with no solo cell produce a sheet that reads *"the team helped"* whether the team helped or the spend did. If solo-at-matched-wall ties the winning team arm, **the finding is that the tree is decorative, and it is worth more than the feature.**

Pre-register in `tools/preregister_m3_a2.py`, refusing without the file, on `fit_gate.py`'s pattern. **Pin `upward_shape` to `Typed` across the whole sweep and record it there**, because arm (b) of A8 spawns a second quarantined child in `validated_headline` and charges `subagents: 1` again at engine.rs:3515-3516 — **two subagents per spawn against a whole-tree cap of 8**, which halves the team. Without that pin the sheet reads "typed crossing beat free text" when it measured "four researchers beat two". Shipped default is `UpwardShape::Typed` (engine.rs:611), so this bites only in the experiment, which is where it matters.

**Cost:** four cells x N questions x ~10 minutes serial wall. A 20-question set is roughly 13 hours per sweep, and it must not share the checkout with a `cargo build` — hazard form 6 inflates every timing ~10% and produces a complete, plausible, wrong table.

### The FACT row, which effort scaling alone cannot move

>= 95% citation accuracy is the only M3 acceptance row with a hard threshold, and ROADMAP names *a separate verification pass for citations* in the same sentence as effort scaling. Raising spend without an instrument for whether it bought CORRECT citations cannot be evaluated against that row. The pass is per-claim and needs no cross-source reasoning — the natural job for the 4b intern, where 22 → 20 AAII is inside the noise and 90 → 150 tok/s is not.

**Its control is mandatory and is the whole point:** seed K claims whose cited source demonstrably does not support them, and report recall on the planted set beside the flag rate on the real set. A verifier with no planted errors reads *"zero problems found"* identically whether it works or returns an empty list.

### The risk, stated rather than designed around

If effort is ever raised by something the sources said — the deferred disagreement field, or any successor — a hostile page buys itself more of the tree's budget and more of the PI's attention. Every source is `UntrustedContent`, so per ADR-036 §5 the floor is saturated and says nothing about any value. It is not an escalation (no tool, no target, no argument); it is resource-allocation influence, and *"is spend a Target under ADR-023"* is undecided and the human's. The shippable form is that any effort input must be a **harness-counted** number — what fraction of a batch was novel, how many chunks reported X — never a model's prose, and it may raise how much is spent while never naming what it is spent on. The cache ratio satisfies that by construction, which is why it ships and the disagreement field waits.
