# ANGLE: The PI's LIFECYCLE — make the latch cheap instead of absent

The latch is only expensive because a latched run's ONLY remaining move is to die, and today's PI dodges it entirely: `engine.rs:3409` pushes every child result at `TrustClass::AgentInferred`, which is above `blocks_composed_targets`, so the PI never latches and composes targets straight out of attacker-shaped summaries (SECURITY-AUDIT finding #1). That is capability bought with a hole. The way out is not to keep the PI unlatched — it is to make a latched run still able to ACT, because `Provenance::taint_for` already has a branch that beats the floor: an argument whose value exactly matches a string the harness attributed carries that string's class, floor or no floor. So the plan artifact must not carry target STRINGS; it must carry HANDLES into namespaces the harness itself minted (the `ScopedPath`s the adjudicator resolved during READ, the doc ids `web` issued and `read_ref` dereferences). An attacker who owns every page can then SELECT among K things the harness already authorized; he cannot NAME a new one. Once that holds, lowering the crossing class becomes affordable, the PI can read the world at full intelligence with its floor on the floor, and phase rotation becomes an optimisation for context economy rather than the thing safety depends on.

## Handle-typed contract fields — `FieldType::Handle` and a harness-minted `HandleSet`

- **What:** A plan/report field that will become a TARGET stops being free text. It becomes a selection from a set of strings the harness itself produced during the READ phase: the `ScopedPath`s the adjudicator resolved for that run, the document ids `web` issued, the tool ids in the run's own `ExposedSet`, the hosts in `EgressPolicy::AllowApproved{granted}`. A value that is not in the set fails validation and the field arrives absent. A value that IS in the set is seeded into the ACT-side `Provenance` at the class its namespace carries. Free-text `Text`/`Line` fields still exist and still carry rationale — they are payload and are treated as such.
- **Mechanism:** `crates/marlowe-loop/src/run.rs`: add `FieldType::Handle` beside `Text`/`Line`; `FieldSpec::validate_value` cannot check it alone (it has no namespace), so add `OutputContract::validate_against(&self, result: &CondensedResult, handles: &HandleSet)` and make the existing `validate` delegate with an empty set (so an unnamespaced caller refuses every `Handle`, fail-closed — the `TaintSet::of` rule applied one level up). `HandleSet` is built in `crates/marlowe-loop/src/engine.rs` from state the harness already holds: `Adjudication.handles` (`marlowe-exec/src/lib.rs:594 handle_for` reads exactly these `ScopedPath`s), the store `read_ref` consults (`marlowe-exec/src/lib.rs:1630-1638`), `run.profile.exposed_tools()`, `run.profile.egress()`. Seeding is one call into `Provenance::attribute` (`crates/marlowe-loop/src/provenance.rs`, §13-guarded, so the boundary hook asks a human — which is correct for the one line that decides what a latched run may name).
- **Gain:** A latched PI can still act. Today `blocks_composed_targets` at `<= UntrustedContent` refuses every model-composed target, so a PI that has honestly read a page is finished: it cannot `edit`, cannot `web`, cannot name a recipient. With handles it can edit any file it actually read, re-fetch any doc it actually fetched, and use any tool it already holds — at full floor-down honesty. The envelope 'you may write to what you read' is exactly the envelope a senior researcher wants, and it is derived from harness state rather than from prose.
- **Cost:** Build: a new `FieldType` variant (every `match` on it is exhaustive today, so the compiler enumerates the sites), a second `validate` entry point, a `HandleSet` type, and one edit to a §13-guarded file. Runtime: a `BTreeSet` lookup per field. What breaks: `OutputContract::structured`'s derived aggregate cap needs a `max_chars` for `Handle` (make it small and fixed, and NOT zero — instance #17: a zero cap here would be a length check that refuses everything while reading as documentation). Every existing contract keeps working because none declares a `Handle` today.
- **Read by:** `OutputContract::validate_against` reads `FieldType::Handle`; `Engine::spawn`'s note match reads the validated handle values and calls `Provenance::attribute`; `Provenance::taint_for` reads `attributed` (its exact-match branch, provenance.rs, already outranks the floor); `marlowe_permission::adjudicate` reads the resulting `TaintSet::of`. Four readers, and each is a line that exists today.

## The crossing class becomes a property of the FIELD, not a constant — closing SECURITY-AUDIT #1

- **What:** `engine.rs:3409` pushes the whole child note as one block at `TrustClass::AgentInferred`. Split it: harness-authored text (the `PauseReason` strings, the violation messages, the receipt) stays `AgentInferred`; contract-validated CONTENT from `Text`/`Line` fields lands at `TrustClass::UntrustedContent`. The PI then latches honestly on its own workers' findings, and `Handle` fields are what keep it able to act.
- **Mechanism:** `crates/marlowe-loop/src/engine.rs` around 3209-3409: the `typed_note` match already separates harness-authored arms from `result.render()`. Emit two `Block`s instead of one — the harness arm keeps `SourceKind::ChildResults` + `AgentInferred` and keeps the `WireTurn` pairing that `unorphan_tool_messages` needs; the rendered content becomes a second block at `UntrustedContent`. `Run::latch_trust_floor` (engine.rs:960, via `view.trust_floor()`) then fires for real, and `Engine::condense_batch`'s trigger — keyed on `blocks_composed_targets`, not on tool name — starts covering child returns too.
- **Gain:** Not a capability gain for the PI; a capability gain for the SYSTEM, and the reason the rest of this angle is honest. It converts the PI from 'never latches, so nothing is measured' into 'latches, and layer 3 is non-vacuous on the one path that carries the most attacker-shaped prose in the product'. It also gives REDTEAM-SESSION pass 2 a taint-class cell that is not discarded (CLAUDE.md: every taint-class zero taken while layer 3 is unreachable reads identically whether the defence holds or every guard is deleted).
- **Cost:** **This is the idea that can kill Marlowe and it must not ship without its guard.** Marlowe receives the PI's final report through the same line. Lower the class and the Secretary latches on his first delegated task and is finished for the life of the process — §2.1's exact failure. The guard is a load-time refusal in `Engine::spawn`: when `run.profile.level() == AgentLevel::Secretary`, a `req.contract` declaring any `Text` or `Line` field is refused by name. That makes M3-DESIGN §2.3's 'typed structure and artifact references, never a paragraph' enforceable instead of conventional — Marlowe's contracts may declare only `Handle` fields and closed enums, so there is no `UntrustedContent` content for him to receive. Prefer the load-time error to a conditional class. Other cost: `condense_batch` now runs on child returns, so a deep tree pays one extra quarantined read per level; bounded by `MAX_SOURCES_PER_READER` and by ADR-041's group-not-call unit.
- **Read by:** `Run::latch_trust_floor` reads the new block's class through `ContextView::trust_floor()`; `Engine::condense_batch` reads it through `blocks_composed_targets`; the new `Engine::spawn` refusal reads `run.profile.level()` and `req.contract.fields[].ty`. No new field.

## `Engine::rotate` — a READ→ACT phase boundary that mints a fresh run from the HandleSet, never from the window

- **What:** When a READ phase completes, the harness starts a new run for the ACT phase, same model, whose window contains only the stable tier plus the rendered plan, and whose `Provenance` is seeded from the plan's `Handle` fields. The 30k tokens of pages do not travel. The READ run's floor is at the bottom and stays there; the ACT run starts at `UserAsserted` because it never read the bytes.
- **Mechanism:** A third floor-setting constructor in `crates/marlowe-loop/src/run.rs` — `Run::rotated(from: &Run, handles: HandleSet, plan: CondensedResult)` — plus `Engine::rotate` in `engine.rs`, built the way `condense_batch` builds a quarantined reader: by named constructor, never through `AgentLevel::child_of`, so no model call can produce one. The plan block is pushed at `UntrustedContent` (idea 2's rule applies to it too); the handles are what let the ACT run act anyway. A `RunSpawned`-style journal row records the rotation, the READ run's id and the handle count.
- **Gain:** Context economy and spawn freedom. A rotated ACT run is unlatched at birth, so `composes_spawn_targets` does not refuse it a child with tools — the one capability handles cannot restore, because a tool grant is not a string in a namespace. And it is cheap: at STATE.md's measured 5,227 tok/s (Ollama) / 6,228 tok/s (llama.cpp) cold prefill, a ~2k-token ACT prefix costs ~380 ms, against re-attending a 30k-token research window on every ACT turn. The 11,410 ms 27b cold load is NOT paid — same model, weights resident, only the KV prefix moves.
- **Cost:** Real and stated. (a) `run.rs` acquires a floor-setting constructor and therefore belongs in `PROTECTED` — with its row added to CLAUDE.md's table in the same commit, per the 2026-08-29 correction. (b) With `OLLAMA_NUM_PARALLEL=1` the READ and ACT prefixes evict each other on a single slot, so every rotation is a cold prefill: rotate coarsely (once or twice per task), never per tool call. Measure it with the existing instrument (`runs/llamacpp/product_ttft.py`), do not argue it. (c) A rotated run cannot see anything the plan did not carry, so a badly-specified contract loses work — the failure is visible (a field absent) rather than silent.
- **Read by:** `Engine::drive` reads the rotated `Run`; `Provenance::taint_for` reads the seeded attributions; `Checkpoint::capture` reads its floor (rotation writes its own checkpoint chain, so a resume of an ACT run restores the ACT floor). No new field.

## Narrow `composes_spawn_targets` — a bounded selection from the parent's own `ExposedSet` is not a composition

- **What:** `engine.rs:3740` refuses a latched run any spawn that names `tools`, `grant_tokens`, a non-`Terminate` orphan, a non-`Worker` role or a non-`Work` disposition. Move `tools` out of that list: a requested tool must already be in `run.profile.exposed_tools()` (the code checks exactly this thirty lines later as a narrowing), so the model is selecting from a harness-held closed set — idea 1's rule, applied to a set that already exists. Keep `grant_tokens`, `orphan`, `role`, `disposition` refused under a latch.
- **Mechanism:** `crates/marlowe-loop/src/engine.rs:3740` plus its destructuring guard test `spawn_request_fields::every_spawn_request_field_is_classified` (engine.rs:3791), which must gain a third category — SELECTION — with its own both-halves assertion: a tool in the parent's set is granted under a latch, a tool outside it is still refused under a latch.
- **Gain:** This is the single biggest capability cliff a latched PI hits. Today a PI that has read anything can delegate only to a child with NO tools — which, per the spawn refusal's own text, means 'do the work in this run', in a run that may no longer compose targets. Removing the cliff means a latched PI still runs a real team.
- **Cost:** Build cost is small; the review cost is not, and this is the one idea I would not ship without the human reading the argument, because it edits the enforcement expression itself. The honest residual: an attacker can steer WHICH of the parent's tools a child holds, which changes what a subsequent human approval prompt is about. Bounded by the narrowing check and by the inherited floor.
- **Read by:** `Engine::spawn` reads `composes_spawn_targets`; the destructuring guard test reads the `SpawnRequest` type itself (its input is the type, not a list — which is why adding a field is a compile error there and #19 does not apply). No new field.

## Re-read by handle instead of holding the page — the PI's context stays small and the information stays reachable

- **What:** The ACT phase does not carry documents; it carries their handles and re-dereferences on demand through `read(ref=…)`, and the re-read goes through the existing group quarantine rather than into the PI's window.
- **Mechanism:** `read_ref` already exists (`crates/marlowe-exec/src/lib.rs:1630`) and dereferences ids `web` issued from a session-scoped store held on `FileSystemTools`. A `ref` supplied by the model is a `Handle` field's value or an id already in the run's `HandleSet`, so it is attributed and survives a latched floor. The returned body is `UntrustedContent`, so `Engine::condense_batch`'s trust-class trigger routes it through a quarantined child exactly as a fresh fetch is routed — no new path.
- **Gain:** The PI's effective research capacity stops being bounded by its context window. It can revisit any of thirty sources at any point in the task at the cost of one quarantined read, instead of choosing at fetch time what to keep. Combined with idea 3, it is what makes a small ACT prefix a capability rather than an amputation.
- **Cost:** Needs verification I could not do read-only: the store lives on `FileSystemTools`, reached through `ports.tools`, and I did not confirm it survives a rotation into a new `Run` within one session. If it does not, rotation loses handle dereference and this idea becomes a store-lifetime change. Latency: a re-read is a fetchless store hit plus one quarantined model call — cheaper than a fetch, not free.
- **Read by:** `FileSystemTools::read` reads the `ref` argument (`text_arg(args, "ref")`, lib.rs:604) and `self.store.get(id)`; `Engine::condense_batch` reads the returned trust class. No new field.

**cheapest_first_step:** Build `HandleSet` over ONE namespace — the `ScopedPath`s the adjudicator already resolved for the run, which `marlowe-exec`'s `handle_for` reads today — plus `FieldType::Handle` and `OutputContract::validate_against`, and prove it with a single engine-level test: a parent whose floor is latched to `UntrustedContent` successfully calls `edit` on a path its READ child returned in a `Handle` field, and is REFUSED on a path that appears only in the child's `Text` field. Both halves, because either alone is green against a broken implementation. Two mutations name it: delete the `Provenance::attribute` seeding and the allow goes red; make `validate_against` accept any string and the refusal goes red. That one test is the entire thesis of this angle — a latched run can act on what the harness vouched for and on nothing else — and it is what tells you whether ideas 2, 3 and 4 are worth their review cost before any of them is written.

**risk_to_the_invariant:** Two routes, and the first is the serious one. **Idea 2 lowers the class at the exact line where a top-agent's report reaches Marlowe.** Ship it unguarded and the Secretary latches on his first delegated task and is finished for the life of the process — §2.1's stated death, arriving as a one-word diff. What prevents it is a load-time refusal in `Engine::spawn`, not a runtime conditional: when `run.profile.level() == AgentLevel::Secretary`, a contract declaring any `Text` or `Line` field is refused by name, so Marlowe can only ever ask for handles and closed enums and there is no untrusted content for him to receive. That makes M3-DESIGN §2.3 enforceable rather than conventional, and it is checkable by mutation — delete the refusal and a test that spawns a `Text` contract from a Secretary-level run goes green, which is the control. The second route is quieter: `Run::rotated` is a **third** floor-setting constructor, and `durable.rs` already names 'a constructor that sets the floor from outside `run.rs`' as the thing to keep to one. Mitigation is that `rotated` takes a `CondensedResult` and a `HandleSet` rather than a `SessionState`, so an untrusted block has no parameter to travel through, plus adding `crates/marlowe-loop/src/run.rs` to `PROTECTED` with its CLAUDE.md row in the same commit. Neither idea gives Marlowe an `ingest` path, a `Channel::Agent` producer, or any untrusted belief; `ingest_external` still has no caller.

# ANGLE: Make the PI's actions cheap to undo, so containment stops being a brake — isolation and rollback as a capability strategy.

The brake on the PI is not the trust floor, it is `bash`'s unconditional `NeedsApproval`: `adjudicate.rs` §5 returns `NeedsApproval` for `ConsequenceLevel::Irreversible` before any tier comparison, and children forward `ports.approvals`, so a PI with ten workers is a prompt storm through Marlowe's TUI. Isolation is worth building because it changes what a human is willing to pre-approve — but a git worktree is a *path* property and `bash` is a *process*, so an arena that does not contain the process buys nothing for the one tool that is actually blocked. The real unlock is amortising the gate: `Outcome::AllowedBatched { batch }` is pinned in CONTRACTS §9 and `decision.rs:103`, is matched as a pass-through at `engine.rs:1982` and `adjudicate.rs:621`, and **has no producer anywhere in the workspace** — a declared seam waiting for exactly this. Two human gates (pre-approve the arena at spawn, review the diff at merge) instead of N gates inside. And there is a load-bearing defect underneath all of it: `FileSystemTools` holds its own `workspace` copy built at daemon boot, so the moment the adjudicator's root becomes per-run, the adjudicator and the executor disagree about where the work happened, silently.

## The run arena — one workspace root per run, carried on the Adjudication

- **What:** The PI's run gets its own git worktree as its workspace root. Every path the adjudicator resolves and every path the executor touches resolves under that root instead of the daemon's single configured workspace. A bad run is `git worktree remove --force`; a good one is one reviewable diff.
- **Mechanism:** `crates/marlowe-loop/src/run.rs`: `Run` gains a workspace root beside `trust_floor`, set by `Run::child` at `Engine::spawn` and by `Run::root` from `DaemonConfig::workspace`. `crates/marlowe-loop/src/engine.rs:1835` currently passes `workspace: &self.workspace` into `Request`; it passes `run.workspace()` instead. `crates/marlowe-permission/src/adjudicate.rs`: `Adjudication` gains the root the decision was made against, beside `handles`. Arena creation/teardown hangs off the two places that already own child lifecycle: `Engine::spawn` and `Engine::settle_children` (which already reads `OrphanPolicy` per parent).
- **Gain:** The PI can create, overwrite and delete without touching the user's tree, so `write`/`edit`/`rm` stop being decisions and become moves. It can attempt an approach, measure it, and discard the attempt without the model having to reconstruct deleted bytes from its own context — today undoing an `edit` requires remembering `replacing`, which `edit` has already deleted. It is also the precondition for two workers ever doing file work without racing on one tree.
- **Cost:** The load-bearing cost is that `FileSystemTools` keeps its own `workspace: PathBuf` built once at daemon boot (`daemon.rs:734`), and reads it at `marlowe-exec/src/lib.rs:1100, 1114, 1371, 1394, 1559`. Line 1559 is `bash`'s `cwd` fallback: move only the adjudicator and a `bash` call with no `cwd` is adjudicated against the arena and *executed in the user's real tree*, while `glob` and `grep` list the real tree under an arena decision. Two sides silently disagreeing, with every existing test green. Second cost: a worktree does not contain `bash` — `cd ..` leaves it — so the arena is a blast-radius reduction for the file tools and nothing at all for the shell until idea 5. Third: worktree create/remove is a `git` subprocess on the turn path, which the heavy-work rule says must not run on the daemon thread.
- **Read by:** `marlowe_permission::scope::open` (existing, unchanged — it already takes the workspace as a parameter); `FileSystemTools::bash`'s `dir` binding and `glob`/`grep`'s `strip_prefix(&self.workspace)`, which must be re-pointed at the root on the `Adjudication`. No new field is read by nothing.

## One approval at the boundary, not N inside — give AllowedBatched a producer

- **What:** A human approves twice per PI task instead of N times: once at spawn ("this run may act irreversibly inside arena X"), once at the merge ("here is the whole diff and the list of commands it ran"). Individual `bash` calls inside the arena carry a batch id rather than raising a modal.
- **Mechanism:** `Outcome::AllowedBatched { batch: u64 }` (`crates/marlowe-permission/src/decision.rs:103`, CONTRACTS §9) is produced by `Adjudicator::adjudicate` when the run carries a live arena grant, in place of the `Irreversible` unconditional `NeedsApproval` return in §5. `Engine::prepare` already treats it as executable at `engine.rs:1982` (`Outcome::Allowed | Outcome::AllowedBatched { .. } => {}`). The grant itself is journalled as `ApprovalGranted` with the batch id, and the merge gate reuses `ApprovalGate::await_approval` with a `BlastRadius` whose `scope` is the arena diff summary and whose `reversible` is true until merge.
- **Gain:** This is the whole unlock. Live evidence in ADR-049 §4 and `builtin.rs`'s own comments: seven attempts to list one directory, each stopping to ask, ending in the model reporting a four-file directory as empty. A PI that can run `cargo test`, `git log`, `sed`, pipes and loops without interrupting the user is a different agent from one that cannot. It also makes an *unattended* PI possible at all — children are spawned `InterruptPolicy::Unattended` (`engine.rs:2891`) yet still route approvals to the human's screen.
- **Cost:** The batch grant is a real widening and must be constructible only from a live arena, never deserialized field-wise (the `ExposedSet`/`CapabilityProfile` lesson, instance #12). `PermissionDecision` gains a `Reason` variant naming why the prompt did not fire, or the journal stops explaining itself. And the grant must be per-run and die with the run, exactly as `EgressPolicy::grant` is per-run — a session-scoped batch grant is the same open question ADR-068 defers and is the human's.
- **Read by:** `Engine::prepare`'s outcome match at `engine.rs:1982` — the existing executor gate. Today that arm is reachable only through `Outcome::Allowed`; this gives the second half a writer.

## Containment as a typed adjudicator input, read at exactly one line

- **What:** Whether a call runs inside a contained arena becomes an explicit input to adjudication, consulted at one place, rather than being inferred or baked into the tool's declared consequence.
- **Mechanism:** `Request` (`crates/marlowe-permission/src/adjudicate.rs:163`) gains `containment: Containment`, an enum with `Ambient` and `Arena { egress_enforced: bool }`. It is read at exactly one site: the `if manifest.consequence() == ConsequenceLevel::Irreversible` return in §5, which becomes conditional on `Containment::Arena { egress_enforced: true }`. `required_tier` is untouched. `Engine` fills it from the run's arena handle; there is no other constructor.
- **Gain:** It is what makes idea 2 legible instead of magical: the reason a `bash` call did not prompt is a named value in `PermissionDecided`, not an absence. It also gives future tools a way to be aggressive-but-contained without renegotiating their manifest.
- **Cost:** **It buys nothing on its own, and that is the finding rather than a caveat.** A worktree is a property of a path; `bash` is a process that can leave it. So `egress_enforced: false` must not relax anything, which restricts the relaxation to tools whose every Target resolved to a `ScopedPath` under the arena — i.e. `edit` and `write`, which are already `Reversible`, already run at `Act`, and already do not prompt. Idea 3 is dead code until idea 5 ships. Building it first would be a declared control nothing reads with a green test asserting the declaration (instance #16, in its purest form).
- **Read by:** One line in `Adjudicator::adjudicate` §5. If that line is deleted the test `an_irreversible_tool_outside_an_arena_still_asks` must go red — mutation-test it, because a boolean that only ever widens is invisible when it stops being consulted.

## Undo without an arena — journal the pre-image where the bytes are already in hand

- **What:** Every workspace mutation writes a signed event carrying the file's previous content, so a wrong edit is one command to reverse rather than a reconstruction exercise for the model.
- **Mechanism:** `FileSystemTools::edit` (`crates/marlowe-exec/src/lib.rs:904`) already reads the entire file into `existing: String` before splicing, under the `self.writes` mutex. `write` (`:842`) opens the target `CreateOrOpen`. A new `EventKind::FileMutated { path, before_blob, after_hash }` in `crates/marlowe-journal/src/event.rs` costs one blob at the exact instant the pre-image is in memory — the journal already has `BlobEvicted`, so blob lifecycle exists. Reversal walks the events for a run in reverse and writes each `before_blob` back through a freshly adjudicated handle.
- **Gain:** Independent of arenas, so it works on the user's real tree and on the day one is not available. It removes a real capability tax: `edit` deletes `replacing`, so a model that wants to undo must have the original bytes in context or re-`read` and re-derive them — observed cost is turns and window. It also gives the human a genuine safety net, which is what makes them willing to grant idea 2's arena in the first place.
- **Cost:** Blob volume on a run that rewrites large files repeatedly; needs a retention rule and it should reuse whatever `BlobEvicted` already implies rather than inventing a second one. It does **not** cover `bash`, which can mutate anything without going through an executor that holds a pre-image — so the coverage claim has to be stated as "file tools only" in the notice text, or it is a safety net that reads as total and is not.
- **Read by:** `Intent::Undo(usize)` — already bound to `^u` (`crates/marlowe-surface/src/app.rs:49`) and `/undo` (`commands.rs:211`), routed at `crates/marlowe-daemon/src/live.rs:342`, where it currently returns `IntentError::NotBuilt { Capability::Undo, M2SessionD }`. The reader exists, is on the keyboard, and is unimplemented. One mismatch to fix rather than inherit: `Notice::Undone { turns }` (`marlowe-view/src/notice.rs:101`) counts **turns**; reporting a file reversal in turns is the adjacent-measurement family again.

## The egress answer: a loopback CONNECT broker, and a process boundary underneath it

- **What:** Give the arena a network destination policy that a shell command cannot spell its way around — and be explicit that the cheap half of this is not containment.
- **Mechanism:** Two separable pieces. **(a) The broker:** a `std::net::TcpListener` on 127.0.0.1 speaking HTTP CONNECT, refusing on the `CONNECT host:port` request line via `EgressPolicy::permits(&Host, manifest.hosts())` — the existing function in `crates/marlowe-permission/src/egress.rs`, with `Host::parse` doing the strict parsing it already does. No TLS interception: CONNECT names the host in cleartext, which is exactly the granularity the allowlist is written at, so `marlowe-net` stays a pure client and ADR-031 §2.3's "the TLS surface is one crate" property is untouched. Child env (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY=127.0.0.1`) is set on the `Command` in `run_bounded` (`marlowe-exec/src/lib.rs`). **(b) The boundary:** the shell is spawned as a dedicated low-privilege local account with a Windows Firewall outbound rule scoped to that SID — deny all, allow 127.0.0.1:<broker> and 127.0.0.1:11434 for Ollama. The child cannot alter that rule without admin.
- **Gain:** This is what converts "isolation" from theatre into the thing that lets a human pre-approve a whole arena. With it, `bash` inside the arena can be `AllowedBatched`; without it, `bash` reaches the network exactly as any process does (ADR-049 §4, measured: `curl` returns HTTP 200) and no policy of any kind is consulted, because the adjudicator's §4 iterates `ParamType::Url` parameters and `bash` declares none. It also finally makes `EgressPolicy` mean something on the path where it currently means nothing.
- **Cost:** The expensive idea here, and honestly so. `CreateProcessAsUser` needs a `windows-sys` dependency `marlowe-exec` deliberately does not have — `run_bounded`'s own doc names that absence as why the Job Object grandchild leak is still open. It needs a one-time elevated install step, which is a product decision. It inherits `VERIFIED_PLATFORMS`' standing obligation: Linux gets a netns/unshare path executed there, macOS stays excluded. Two leaks it does not close and which must be written down rather than implied: `git push` from the arena is egress through whatever forge host the broker allows, and Ollama on loopback must be reachable, so a contained shell can talk to the model directly. The verification is a pair, not a single command — `curl https://example.com` must return a broker refusal *and* `curl http://127.0.0.1:11434/api/tags` must return 200, with the same pair run against containment disabled giving the opposite result. One command alone would read identically if the whole thing were inert.
- **Read by:** `EgressPolicy::permits` and `crate::egress::declared_admits` — both existing, both already the enforcement site on the `web` path. The broker adds a second caller of the same function rather than a second definition of the policy, which is the point.

**cheapest_first_step:** Not the worktree. Make `Adjudication` carry the workspace root the decision was made against, and make `FileSystemTools` read *that* instead of its own `self.workspace` — five sites: `marlowe-exec/src/lib.rs:1100, 1114, 1371, 1394` (glob/grep `strip_prefix` and one `scope.open`) and `:1559` (`bash`'s `cwd` fallback, `unwrap_or_else(|| self.workspace.clone())`). Today both paths are the same directory, so the change is behaviour-neutral and cannot regress anything. It is mutation-testable in the way this project asks for: point the adjudicator at directory A and the executor's copy at directory B, and `bash` with no `cwd`, `glob`, and `grep` must all fail or refuse — if any of them silently operates in B, the defect is live in the shipped binary the day an arena exists. It closes the two-definitions hazard *before* anything depends on it, it is the seam every other idea on this page needs, and it costs an afternoon. Second cheapest, independently: write the one-line grep that proves `Outcome::AllowedBatched` has no producer (`grep -rn "AllowedBatched" crates/ --include=*.rs` returns three hits, all readers) and record it in `SECURITY-AUDIT.md` as a pinned contract variant with no writer, so idea 2 arrives as filling a declared seam rather than as a new mechanism.

**risk_to_the_invariant:** Nothing here gives Marlowe a reader, and the arena is per-run, so Marlowe's permanent run is simply the one whose root is the real workspace. The single place it could bite is the merge report. If the PI's diff reaches Marlowe's window as raw child bytes at a lowered class, Marlowe latches — for that turn today, and permanently once ADR-068's session latch is built, which is the shape D makes live. Today's path is safe by measurement, not by design: a child's report crosses at `AgentInferred` (SECURITY-AUDIT #1), above `blocks_composed_targets`'s threshold. The rule to pin before anything is built is that what crosses into Marlowe is harness-authored — a file count, a path list, a command list, and a reference — never the child's prose or the diff body at a class the harness did not choose. That is `Engine::spawn`'s `let note = match self.upward_shape` already doing exactly this job, and it should stay the one hop. Secondary risk: idea 2's batch grant is a real widening, and if it is ever made session-scoped rather than run-scoped it becomes the same unresolved question ADR-032 §3.1 and SECURITY-AUDIT §8 both raise. Keep it per-run, dying with the run, exactly as `EgressPolicy::grant` does — and note that `grant` lives on the profile precisely because putting it on the `Run` would bypass `CapabilityProfile::new`'s invariant rather than enforce it. The batch grant belongs in the same place for the same reason.

# ANGLE: The adversary's angle: every code path that can latch Marlowe, which of them a more capable PI makes more likely, and what a PI may therefore never be permitted regardless of how good the model is.

Marlowe cannot latch today, and it is not because anything guards him. `engine.rs:960` is the only production `latch_trust_floor` call and it reads `ContextView::trust_floor()` = min over the blocks in the view; after ADR-041 every untrusted tool result is diverted to a quarantined child and re-enters at `AgentInferred` (`engine.rs:2246`), a child's report is hardcoded `AgentInferred` (`engine.rs:3409`), compaction and the trim marker now `min` rather than stamp, and the only block that can carry `UntrustedContent` into a parent is `SourceKind::InjectedMemory` at `daemon.rs:2753` — whose class comes from a belief that cannot be `UntrustedContent` because `ingest_external` has no caller and `remember` is circular. **The invariant is protected by exactly the same unreachability that makes layer 3 vacuous.** They are one fact, and ADR-062 §4 flips both at once. Second finding: M3-DESIGN §3.2's "a notification and nothing else" is enforced in code for **escalations only** (`escalation.rs`: `Recipient` has no `Secretary` variant, `EscalationPort` has one method returning an id). The ordinary completion path is unguarded — `Engine::spawn`'s note match renders the PI's contract fields into a `ChildResults` block that lands in Marlowe's **persisted** `SessionState` (`daemon.rs:2886`) and survives turns. Validation is length and character class, no semantics. A richer PI produces a richer report and it crosses verbatim. Third: the real capability tax on the PI is not the permission layer at all — it is that the AAII-52 senior researcher reads every document through a fixed harness contract ("what these sources say, for someone who will not see them") capped at 1,500 characters per source, six sources per reader, with no way to say what he needed.

## The Secretary abstains from an untrusted belief instead of ingesting one

- **What:** Marlowe's turn refuses to build an `InjectedMemory` block when the retrieved floor is at or below `UntrustedContent`. He is told a relevant memory exists and that it is untrusted, and nothing else — the §3.2 shape applied to memory instead of to escalations. He can then spawn a PI to read it, which is what a liaison is for. This converts the invariant from unreachable-therefore-safe into enforced-and-testable, at zero behavioural cost today because the branch cannot fire yet.

- **Gain:** None for the PI directly. What it buys is permission to build everything else: with this line in place, `ingest` can be wired, the PI can be given memory writes, and a poisoned belief costs Marlowe a retrieval rather than his ability to compose a target for the rest of the conversation. The real cost is a decision the human owns: Marlowe permanently knows less than his store does, and §B1 forbids showing the user why. The failure mode to watch for is Marlowe improvising an explanation, which M3-DESIGN §3.3 already answers with a stable-tier sentence — that sentence has to exist before this ships or the abstention is invisible and inexplicable.
- **Read by:** No new field. The new branch reads `Retrieved::floor` through `marlowe_permission::blocks_composed_targets`, which already has three readers (`adjudicate.rs:51`'s enforcement, `engine.rs:985`'s banner gate, `engine.rs:2151`'s layer-1 divert).

## Scope the READ, not the write — give the PI durable memory and keep it out of Marlowe's retrieval

- **What:** The reason the PI has no memory today is that `memory: None` is hardcoded at all three child `Ports` sites, which withholds the capability structurally but also withholds it completely: a senior researcher on a long task cannot accumulate anything across its own children. Invert it. Let a top-agent hold `MemoryWrite`, and make the containment a property of what the Secretary's retrieval is allowed to see. Marlowe's window is protected by the read scope; the PI's usefulness is bought by the write.
- **Mechanism:** `crates/marlowe-loop/src/engine.rs:3175` (the ordinary spawn's child `Ports`) passes `ports.memory` when `child_run.profile.level()` is `TopAgent`, and keeps `None` at 2458 and 3506 (the two quarantined readers — those must never change, `CapabilityProfile::new` already refuses `reads_untrusted && may_write_memory`). The containment goes on the belief: a `Scope` field on the claim, set from the writing run's `AgentLevel` inside `DaemonMemory::remember` (`crates/marlowe-daemon/src/memory.rs`), and read by the candidate filter in `DaemonMemory::retrieve` / `select_for_injection`, which today scopes only on `e.source_session_id`. `Scope::Conversation` must be constructible only from a `Secretary`-level write, so widening it is a type change and not a config change — the `ExposedSet::empty()` precedent, not a counter at zero.
- **Gain:** The PI accumulates findings that outlive one child return and one context window — the thing that actually limits a long research task, since today everything a worker learned is compressed into a contract's fields and then dropped. It also makes the ladder's economics work: an intern's extraction can be written once and read by three assistants instead of being re-derived per branch.
- **Cost:** Real work: a new field on the belief, a store migration, and the `Scope` enum has to be constructed in exactly one place or it is instance #16 with a `Serialize` derive. It also depends on ROADMAP M3 Session D landing first. And it must not ship before idea 1 — a PI writing memory is the first mechanism that puts model-derived durable text anywhere near the permanent run, and idea 1 is the line that makes the class check exist at all.
- **Read by:** `Scope` is read by the candidate filter inside `DaemonMemory::retrieve` (`crates/marlowe-daemon/src/memory.rs`) and by `recall`'s `recall_candidates()` consumer in `crates/marlowe-daemon/src/recall.rs:63`. `Ports::memory` is already read by `Engine`'s `ModelStep::MemoryWrite` arm.

## Let the PI write the reader's brief — the largest capability gain in the list, and it changes no containment at all

- **What:** Every untrusted document the PI touches is read by a quarantined child under a contract the harness authored: `OutputContract::structured("what these sources say, for someone who will not see them", [about@600, source_i@1500])`, at most six sources per reader. The senior researcher gets 1,500 characters of a 40-page paper, extracted against a question nobody asked. Make the reading brief a payload the spawner supplies: what to extract, which fields, what to ignore.
- **Mechanism:** `crates/marlowe-loop/src/engine.rs:2320-2328` builds `fields` and `contract` from constants. Take them instead from a per-run reading brief the PI sets — either an optional `extract` parameter on `read`/`web` carried through `PendingRead` (which already holds `tool`, `text`, `summary`, `call_ref`), or a `SpawnRequest`-level brief inherited by the run. The contract description and the `FieldSpec` names become model-authored; `PER_SOURCE_MAX_CHARS` stays a harness cap. `OutputContract::validate` is unchanged and still checks names and lengths.
- **Gain:** The difference between "summarise this" and "pull the ablation table, the eval split, and any sentence that contradicts X" across thirty documents. - **Read by:** The new brief is read by `OutputContract::structured`'s argument construction at `engine.rs:2320-2328` and, through `contract.description`, by the child's `SourceKind::Brief` block at `engine.rs:2485`. ## A self-protection deny-set inside path scoping: `crates/`, `persona/`, the journal, `.claude/`

- **What:** The PI holds `edit` and `write`, both declaring `WORKSPACE = "./**"` (`crates/marlowe-tools/src/builtin.rs:315`), both `Reversible`, both allowed at `Act` with no prompt. The human's decision to give the senior researcher working tools is right, and it is only defensible if the tools cannot reach the machinery that decides what tools mean. With this in place you can hand the PI `edit`, `write` and a wide scope without the argument having to route through "but it probably won't".

Path canonicalisation on Windows is where this gets subtly wrong (symlinks, `\\?\` prefixes, case), and a deny-set that fails open on a path it cannot canonicalise is worse than none — it must fail closed and say so.
- **Read by:** `self_root` is read by the deny check inside `marlowe_permission::scope`'s resolve, called from `adjudicate`'s scope step; and by the daemon's boot guard that refuses to start when it lies inside the workspace. If no function reads it, it is instance #16 and should not be added.

## `bash` is not the PI's tool until ADR-049 §4 closes

- **What:** The PI's exfiltration leg. `adjudicate`'s egress step iterates parameters typed `ParamType::Url`; `bash` declares none, so no `EgressPolicy` is consulted on that path at all — measured, `curl` returning 200 from `cmd /C`. - **Read by:** No new field. The `TopAgent` arm's refusal is read by `CapabilityProfile::new`, which `Engine::spawn` calls; the new tools' `hosts()` is read by `marlowe_permission::egress::declared_admits` at `adjudicate.rs:374`, which already exists and already has that reader.

**cheapest_first_step:** Idea 1's branch at `crates/marlowe-daemon/src/daemon.rs:2753`, with its vacuity control. Roughly twenty lines: guard the `InjectedMemory` push on `marlowe_permission::blocks_composed_targets(retrieved.floor)`, push nothing on the refusing path, journal what was withheld. Two tests: hand-write an `UntrustedContent` belief into a real store, retrieve, assert no `InjectedMemory` block and `run.trust_floor() == AgentInferred` after the turn; and the negative control that a clean belief still injects, so the test is not green on \"injection is broken\". It fires on nothing today, which is the point — it converts the invariant from unreachable to enforced, it is the one line that must exist before `ingest` ever gets a caller, and it is also the first coverage on that production push at all: `crates/marlowe-daemon/tests/layer3_refuses_a_composed_target_from_an_ingested_belief.rs` substitutes its own version of that line, and mutation showed the real one can be laundered to `UserAsserted` or deleted outright with the whole daemon crate staying green (`runs/m3-mutation/finding1*.txt`).

**risk_to_the_invariant:** The invariant is currently satisfied by an accident of reachability, not by a guard. Two secondary hazards worth naming. Second, `Degraded{TrustFloorLatched}` is not evidence about any of this: instance #15 established it fires on every run that has ever run, and `engine.rs:985` now gates only the *screen* on `blocks_composed_targets` while the journal still records every move. Ask `marlowe_permission::blocks_composed_targets`, never the event.

# ANGLE: Per-VALUE provenance instead of a run-wide latch — the blunt instrument problem

The per-value machinery is fully built and correct — `adjudicate.rs`'s §2 loop already walks `req.args`, reads `manifest.role_of(name)`, and blocks only `ArgumentRole::Target` values whose own `taint.of(name)` trips `blocks_composed_targets`. The blunt instrument is not the adjudicator; it is `Provenance::taint_for`, which has exactly two producers — an exact-string match against tokens the user typed, and `view.trust_floor().min(latched)` for everything else. So for every model-composed value the TaintSet is a **constant function of the run**, and per-value provenance carries zero per-value information. That is one half of the finding. The other half is bigger and I verified it in code: **the run-wide floor does not currently hinder the PI at all, because it can no longer latch.** `Engine::finish_call` (engine.rs:2152) diverts every result where `blocks_composed_targets(outcome.trust)` into `PendingRead`, and `condense_chunk` pushes it back at `TrustClass::AgentInferred` — no `UntrustedContent` block ever enters a parent's `SessionState`, so `ContextView::trust_floor()` never reaches the threshold and `blocks_composed_targets(run.trust_floor())` is false in every parent run. The thing that actually taxes the PI is **layer 1's implementation choice**: `CapabilityProfile::quarantined_reader()` hardcodes `ModelRoute::Worker` (profile.rs:361) and `PER_SOURCE_MAX_CHARS = 1_500` (engine.rs:71), so the AAII-52 senior researcher never reads a source — he reads 1,500 characters per document written by the cheapest model in the ladder, six documents to a reader. That is the capability ceiling, and lifting it costs nothing security-wise because containment in that child is structural (`ExposedSet::empty()`, `DenyAll`, `OutputContract::validate`) and not model-dependent. Per-value provenance is what you build *second* — it is the thing that makes a latched PI survivable rather than dead, so that raw untrusted text can eventually reach the PI's window at all.

## Route the quarantined reader at the spawner's own model tier

- **What:** `CapabilityProfile::quarantined_reader()` pins `ModelRoute::Worker`. Every untrusted document the PI will ever see is therefore read and summarised by the cheapest column in `Routing` — Agent-Low, AAII 20 — and the PI (AAII 52) receives only that model's 1,500-character prose. Replace the constructor with `quarantined_reader_for(route: ModelRoute)` and have `condense_chunk` pass `run.profile.model_route()`, so a 27b PI's reader is the 27b. Raise `PER_SOURCE_MAX_CHARS` in the same change and let it be a function of the contract's aggregate rather than a bare constant.
- **Mechanism:** `crates/marlowe-loop/src/profile.rs:358` (`quarantined_reader`, the `ModelRoute::Worker` literal); `crates/marlowe-loop/src/engine.rs:2338` (`condense_chunk`'s `Run::child(..., CapabilityProfile::quarantined_reader(), ...)`); `crates/marlowe-loop/src/engine.rs:71` (`PER_SOURCE_MAX_CHARS`); `crates/marlowe-loop/src/engine.rs:2326` (`FieldSpec::text(&source_label(i)).capped(...)`).
- **Gain:** The senior researcher's understanding of every source stops being bottlenecked by the intern. Today a 40-page paper reaches the PI as 1,500 characters of Agent-Low prose; after this it is 1,500+ characters of Agent-High prose, from a model that can actually tell which paragraph mattered. This is the single largest fidelity gain available and it is a two-line change.
- **Cost:** Build: ~10 lines plus threading `run.profile.model_route()` into `condense_chunk`. Runtime: on this 16 GB card it is **cheaper**, not dearer — `AGENT-DIRECTORY.md` §2 states two roles sharing a model share weights and multiply only the KV cache, so routing the reader to the parent's already-resident model avoids the second set of weights that `ModelRoute::Worker` currently demands. With `OLLAMA_NUM_PARALLEL=1` the reader already serialises behind the parent, so no new contention. Longer summaries cost parent context. What breaks: `agent_levels.rs:234` and `profile.rs:740` name the zero-arg constructor and need updating; the `Summarizer` column is untouched.
- **Read by:** New parameter `route` on `quarantined_reader_for`, stored in the existing `CapabilityProfile::model_route` field, read by the existing chain `Budget::call_limits` → `CallLimits::route` → `OllamaDriver::request_body` → `Routing::model_for` (`crates/marlowe-provider/src/routing.rs:67`). No new field.

## The taint clock — a composed-value ledger, first composition wins

- **What:** Give `Provenance` a third source of truth between attribution and the floor: a ledger of values that were arguments of an **allowed** call, recorded with the floor as it stood at that moment. `taint_for` consults attributed → composed ledger → floor. A value the model composed while the window was clean keeps its clean class after the floor drops, because the untrusted text did not exist when the model wrote it.
- **Mechanism:** `crates/marlowe-loop/src/provenance.rs`: add `composed: BTreeMap<String, TrustClass>` beside `attributed`, plus `fn record_composed(&mut self, args: &Args, floor: TrustClass)` with **first-write-wins** semantics (deliberately not `attribute`'s `min`-merge — that is the whole point and the reason it cannot reuse `attribute`). Called from `Engine::finish_call` (engine.rs, after the `Outcome::Allowed` path) so only calls that actually ran insert. `Provenance::taint_for` gains one lookup between the `attributed.get(s)` and the `unwrap_or(floor)`. Checkpointing: `crates/marlowe-loop/src/durable.rs:145` rebuilds `Provenance` by replaying user messages only, so the ledger comes back **empty** on resume — fail-closed, and worth stating in the doc comment rather than fixing.
- **Gain:** The concrete PI workflow that is impossible today the moment anything latches: create `runs/report.md` while clean, read thirty sources, then keep appending to it. Under the run-wide floor that path is `UntrustedContent` forever. Under the clock it is whatever it was when the PI first wrote to it. This is what turns 'a latched run is dead' into 'a latched run keeps the ground it already took'.
- **Cost:** Build: ~40 lines and three tests. The residual channel is **selection**: an attacker who arrives later can steer the model toward re-using one entry, giving log2(|ledger|) bits of target choice over a set the attacker did not author. Bound it by inserting only from allowed calls (never from prose, never from blocked calls) and capping the map; state the bandwidth in the ADR rather than claiming it is zero. What breaks: nothing existing — the lookup is a new branch that can only return a class the run already had.
- **Read by:** `Provenance::taint_for` (crates/marlowe-loop/src/provenance.rs) is the sole reader of `composed`, and it is the sole producer of the `TaintSet` that `adjudicate`'s §2 loop reads. Mutation test that keeps it honest: delete the lookup and `a_target_first_written_before_the_taint_is_still_writable_after` goes red; delete the *insert* and it goes red too, which is what stops the ledger becoming a declared control nothing writes (#16's mirror image).

## Approval attribution — a human who reads a target has asserted it

- **What:** When a call reaches `Outcome::NeedsApproval` and a person approves it, attribute every declared Target in that call at `UserAsserted`. The human read the exact strings: §B9's blast radius line is built from `manifest.params().filter(role == Target)` and rendered by `ArgValue::render`, so what was on screen is exactly what would be attributed. This is `EgressPolicy::grant` / `CapabilityProfile::grant_egress_host` (ADR-032 §3.1) applied to targets instead of hosts — the precedent, and the widening-with-its-mutation-tests discipline, already exist.
- **Mechanism:** `crates/marlowe-loop/src/engine.rs`, the branch that handles the approval gate's positive answer (the same site that today calls the egress grant); call `provenance.attribute(value, TrustClass::UserAsserted)` for each param where `manifest.role_of(name) == Some(ArgumentRole::Target)`, taking the values from `PermissionDecision::blast_radius.scope` inputs rather than re-deriving them — the adjudicator already names them, exactly as it names the egress host so the loop does not re-walk the manifest. Scope: the run, mirroring the egress grant's per-turn `Run::root` scope.
- **Gain:** A latched PI is no longer mute. It can ask about one novel target, get a yes, and keep working — instead of every subsequent composed target being refused with no path to recovery. It also gives the PI a *legible* way to escalate that is not 'spawn a fresh child to launder it'.
- **Cost:** Build: ~20 lines, plus the negative-control test that a *declined* approval attributes nothing. Runtime: prompt fatigue is the real cost — a latched PI that must ask about each new path will ask a lot, which argues for landing idea 2 first so the common case never asks. What breaks: raises the value of a mis-rendered approval prompt, so `every_arg_value_variant_renders_to_something_a_human_can_read` becomes load-bearing for a second reason.
- **Read by:** No new field. Writes into the existing `Provenance::attributed` map, whose only reader is `Provenance::taint_for`. The values written come from `PermissionDecision::blast_radius` (adjudicate.rs `blast_radius`), which is the same structure the surface renders — one definition of *which strings this call is about*, read at both ends.

## Attribute the resolved handle, not the string the model typed

- **What:** `Adjudication.handles: BTreeMap<String, ScopedPath>` already carries the paths the adjudicator opened, and adjudicate.rs's header insists the executor use the handles rather than re-resolving. Nothing, however, attributes the resolved path back into `Provenance`. Do it: on an allowed call, `attribute(handle.as_str(), AgentObserved)` for each opened handle. `Provenance::attribute`'s own doc already names 'resolved paths' as an `AgentObserved` source — the producer was simply never written.
- **Mechanism:** `crates/marlowe-permission/src/adjudicate.rs` (`Adjudication.handles`, populated in check §3 by `self.scope.open(...)`) → `crates/marlowe-loop/src/engine.rs`'s `finish_call`, which already destructures `PreparedCall { adjudication, .. }`. `Provenance::attribute` (crates/marlowe-loop/src/provenance.rs) is the sink; it already exists and already `min`-merges.
- **Gain:** Small but free, and it removes a class of maddening refusal: the PI writes `./runs/x/report.md`, the scope layer resolves it to a canonical absolute path, and on the next turn a call naming the canonical form is a stranger to `attributed` and falls to the floor. Two spellings of one file, one of which the harness itself produced. Attributing the resolved form makes both usable.
- **Cost:** Build: ~15 lines. Risk: it enlarges the attributed set over a long session, which is the growth problem idea 6 exists to bound — land them together or the two changes pull opposite ways. What breaks: nothing; no existing test asserts that resolved paths are *un*attributed.
- **Read by:** `Provenance::taint_for`. No new field — `Adjudication.handles` already exists and is already consumed by the tool host; this adds a second consumer at the same site.

## Verbatim quotes by offset — raise the PI's bandwidth while narrowing the child's channel

- **What:** Add a `FieldType::Quote` whose value is not prose but a span reference: the quarantined child returns offsets into the source it was given, and the harness slices `PendingRead.text` — which it still holds — and substitutes the literal bytes. The PI then reads the source's actual sentences instead of an intern's paraphrase of them. The child's expressive channel shrinks from 1,500 characters of arbitrary prose to a pair of integers per quote.
- **Mechanism:** `crates/marlowe-loop/src/run.rs:271` (`FieldType`), `FieldSpec::validate_value` (the length-then-character-class check), `OutputContract::structured`; substitution in `crates/marlowe-loop/src/engine.rs`'s `condense_chunk`, which holds `chunk: &[PendingRead]` and therefore the raw text. The sliced text must still pass `marlowe_contract::text::is_renderable` — an attacker-chosen span is exactly where an `ESC` byte would ride in, and that check is the one thing standing between a fetched page and a terminal.
- **Gain:** The difference between 'a source says transformers scale' and the actual claim, numbers and caveats. For a research PI this is the whole job. It also makes the PI's final report citable to real text rather than to a chain of paraphrases.
- **Cost:** Build: the largest of these — a new `FieldType` variant, a parser for span references, offset validation against the actual source length, plus a whole family of tests (out-of-range offsets, overlapping spans, spans chosen to splice two sentences into a third meaning). Runtime: parent context. What breaks: this is the change that finally makes layer 3 reachable in a parent run, which means every 'layer 3 holds' claim goes from unreachable-and-vacuous to live-and-load-bearing overnight. Do not ship it before red-team pass 2, and do not ship it before ideas 2–4, or a PI that reads one source can never write again.
- **Read by:** `FieldSpec::validate_value` (crates/marlowe-loop/src/run.rs) reads `ty` to decide the character class, as it already does for `Text` vs `Line`; `condense_chunk` reads the variant to decide whether to substitute. `CapabilityProfile::new`'s level match reads the new profile predicate and returns `ProfileError`.

## Bound the attributed set — the loosenings have to be paid for

- **What:** `Provenance.attributed` grows monotonically for the life of a session (`SessionMemory` holds it, daemon.rs:669; `attribute_user_message` inserts the whole message **and every whitespace token** on every user message and every steer) and it is keyed on the value string alone with no notion of which parameter the value is legal for. So a word the user typed as a search term is a `UserAsserted` `bash` `cwd`, forever. - **Mechanism:** `crates/marlowe-loop/src/provenance.rs` — `attributed: BTreeMap<String, TrustClass>` becomes `BTreeMap<String, (TrustClass, Generation)>`; `taint_for` already receives the `Args` and can be given the `&CapabilityManifest` to call `role_of`, which `adjudicate` already does. `crates/marlowe-daemon/src/control_plane.rs:409` and `crates/marlowe-loop/src/steer.rs` (§13-guarded) already document the unbounded-steer form of this as a live hazard.
- **Gain:** None directly — this is the price. Its purpose is that ideas 2, 3 and 4 each add a way for a value to be trusted, and without a bound the three of them turn `attributed` into the laundering surface `control_plane.rs` already warns about.
- **Cost:** Build: moderate; `taint_for`'s signature changes and every test in provenance.rs and adr023_live.rs is touched. Risk: a decay window chosen too short makes the PI ask about paths the user typed two minutes ago, which reads as a regression to the user. Pick the generation boundary as the user *turn*, not a clock — §4.5 forbids clock reads on this path and a wall-clock decay would put one there.
- **Read by:** `Provenance::taint_for` reads the generation and the role; `Engine::run_turn` (crates/marlowe-loop/src/engine.rs, the site that already calls `attribute_user_message` at :1055) increments the generation. No field is added that nothing reads.

**cheapest_first_step:** Idea 1, and it is roughly ten lines. Change `CapabilityProfile::quarantined_reader()` (crates/marlowe-loop/src/profile.rs:358) to take the spawner's `ModelRoute` instead of the hardcoded `ModelRoute::Worker`, and have `condense_chunk` (crates/marlowe-loop/src/engine.rs:2338) pass `run.profile.model_route()`. It touches no security property (containment in that child is `ExposedSet::empty()` plus `DenyAll`, both structural and both load-time enforced), it is VRAM-cheaper on this card rather than dearer, and the assertion is not a proxy: dump the outbound request body under `--dev` and read the `"model"` field of the bytes the running daemon sent for the reader's call — the same instrument that closed the persona's pipe-tested-guard, and it reads differently the moment the route is wrong.

**risk_to_the_invariant:** Marlowe latches only if an `UntrustedContent` block enters the one permanent run's `SessionState`. None of ideas 1–4 or 6 can push a block of any class — they only change which model serves a harness-built child, and which values `taint_for` classifies above the floor, both of which move trust upward and neither of which constructs a `Block`. **Idea 5 is the one that can, and it is the reason idea 5 is last.** Its danger is not that someone would deliberately give Marlowe raw quotes; it is that the quote path would be implemented as a profile flag (`reads_raw_untrusted: bool`) that defaults false, and a later session would flip it in a config or a `Deserialize` and every test would stay green — the twelfth instance's exact shape. Finally, none of this may be scoped to the *session*: the egress grant deliberately lives on `Run::root`'s per-turn profile, and `SECURITY-AUDIT.md` §8's *'the latch belongs on the session, not the Run'* is an open question that is the human's. Placed in `Engine::spawn` that guard misses `validated_headline`, which builds its child with a direct `Run::child(...)` and never passes through `spawn`; placed in `Run::child` it KILLS `validated_headline`, whose contract is a `FieldSpec::line` — A8 arm (b), and M3-DESIGN §2.3's own "one quarantine-validated sentence". With the `min` instead, Marlowe's floor moves only when a child actually read untrusted content, and his exposure to research is handled where the design already put it — arm (b)'s quarantined headline and §3.2's notification-only escalation.

**Free today, and the largest real capability item: re-read by `ref`.** `read` is Inert, so a latched PI can already deref any document; `builtin.rs`'s own comment on the `ref` parameter says the role check "has no reader on any enforcing path". The `DocumentStore` lives on `FileSystemTools` (marlowe-exec/src/lib.rs:314), built once at daemon.rs:734, so it is daemon-scoped and survives every spawn. This needs a PROMPT change telling the PI to fetch wide, drop pages, and re-deref — zero code, zero review, available now. Record the pre-existing residual: nothing checks WHICH ref a latched run derefs.

**DROPPED. (1) `Engine::rotate`.** Its structural argument is false — no `Run` constructor takes a `SessionState` (`root`, `child`, `restored` all take neither), so "no parameter for a page to travel through" is vacuous and the safety lives entirely in unguarded engine code. And the arithmetic does not work: a rotated run pushing its plan at `UntrustedContent` re-latches on its first assemble, so it buys context economy only — and if the plan crossed above the threshold it would be finding #1 relocated into a third floor-setting constructor (`Run::restored` is already the second). If revived it must be `Run::rotated(...) -> (Run, SessionState)`, building the window itself, with `run.rs` added to `PROTECTED` and its CLAUDE.md row in the same commit. **(2) Widening `composes_spawn_targets`.** The child inherits the parent's floor (run.rs:667) and gets `Provenance::new()` — "the child does not inherit the parent's attributions" (engine.rs:3104) — so a latched parent handing `edit` to a child produces a child that also cannot edit, and handles do not compose with spawns. The whole gain is delegated READING, obtainable without touching layer 3's boolean by exposing the parent's Inert tools in the latched-parent default child profile.

**Cheapest first step, with mutations that discriminate.** One engine-level test, three assertions: a parent latched to `UntrustedContent` (a) succeeds at `edit(path=…)` on a path returned in a `Handle` field it already holds; (b) is refused on a path appearing only in a `Text` field; (c) is still floored when that same handle string is passed as `bash`'s `cwd`. Three mutations, one per assertion: delete the `attributed_targets` seeding → (a) reddens; seed from every field regardless of `ty` → (b) reddens; key the seeding by value alone → (c) reddens. The angle's proposed mutation for (b) — "make `validate_against` accept any string" — does NOT redden it, because a `Text` value is never a seeding candidate; and (b) is green today against an entirely unimplemented feature, so on its own it is not evidence.
