Marlowe is a terminal-native agent harness — the runtime around a local language model that gives it memory, tools, durable execution, and earned autonomy. Everything it knows, is doing, or has done is a materialized view over one append-only, provenance-signed event log, and the agent loop is a transaction that reads a view, acts, and appends. The harness is a Rust workspace; `eval/` is a separate Python scoreboard that scores it and is never modified to accommodate it.

Run it with `cargo build --release`, then `target/release/marlowe.exe --launch` to open a terminal Marlowe configures for itself, or `--tui` to stay in the current one — either way the client auto-spawns the daemon, so `marlowe --serve` is only needed when you want to run it yourself. There is no default mode: every invocation names one. It needs Ollama serving `qwen3.5:9b` and a terminal of at least 120x30.

One number, measured rather than estimated: **65.3 ms to first token against 313.4 ms, 4.8x**, llama.cpp and Ollama serving the same GGUF blob on one RTX 4080 SUPER — median of 11 warm reps per arm, on the daemon's own clock, with the whole turn (501 ms vs 778 ms) moving the same way. Ollama is what ships: the llama.cpp path is opt-in via `--provider llamacpp` and is shelved on tool-call parsing, not on speed.
